# ChronosLOB Label Engine

Phase 4 adds deterministic future-window labels for short-horizon
market-state forecasting. The label engine lives in `chronoslob.labels` and
is separate from `chronoslob.features`.

## Implemented Labels

The generated label frame can include:

- `future_return_{h}`: mid-price return from row `t` to row `t + h`.
- `direction_{h}`: `up`, `down` or `stationary`, based on a configurable return
  threshold.
- `return_quantile_{h}`: empirical return bucket fitted on the supplied return
  series for that call.
- `future_volatility_{h}`: realised volatility over prices from `t` through
  `t + h`, using `sqrt(sum(log_return ** 2))`.
- `spread_widening_{h}`: whether the future spread increase exceeds a threshold.
- `bid_fill_proxy_{h}` and `ask_fill_proxy_{h}`: simplified passive-fill proxy
  labels.
- `bid_adverse_selection_proxy_{h}` and `ask_adverse_selection_proxy_{h}`:
  simplified adverse-selection proxy labels after a proxy fill.

Horizons are event or row horizons, not clock-time windows. Each generated
`LabelRow` records `timestamp`, `horizon_start` and `horizon_end`. For horizons
longer than one row, `horizon_start` is the next snapshot timestamp and
`horizon_end` is the timestamp at the maximum requested label horizon. For a
one-row horizon, `horizon_start` is the row timestamp so that the existing
`LabelRow` invariant `horizon_end > horizon_start` remains true.

## Formula Notes

Future log return:

```text
log(mid_price[t + h] / mid_price[t])
```

Future simple return:

```text
mid_price[t + h] / mid_price[t] - 1
```

Future realised volatility:

```text
sqrt(sum(log(mid_price[i] / mid_price[i - 1]) ** 2))
for i in t + 1 ... t + h
```

Spread change:

```text
spread[t + h] - spread[t]
```

## FI-2010 Benchmark Labels

`build_label_frame_from_fi2010` distinguishes two cases:

- If the dataset has configured existing labels and `prefer_existing_labels=True`,
  those columns are preserved as FI-2010 benchmark labels and the frame carries
  `label_source = "fi2010_existing_labels"`.
- If existing labels are unavailable or not preferred, labels are generated from
  `OrderBookSnapshot` rows produced by the local loader.

Existing FI-2010 labels are not presented as labels generated by ChronosLOB.

## Missing Future Data

Low-level label functions support `missing="drop"` and `missing="none"`.
Generated `LabelRow` objects currently use a drop policy because `LabelRow`
does not permit `None` label values. Trailing rows without enough future data are
therefore omitted from generated label rows and frames.

## Proxy Limitations

The fill-probability label is a passive-fill proxy. It observes top-of-book
quantity decreases at the original price or a top-of-book price move through the
original price. It does not know queue position, order size, latency, partial
fills, hidden liquidity or venue matching rules.

The adverse-selection label is also a proxy. It first requires a proxy fill, then
checks whether the evaluation mid-price moved against the passive side by more
than a simple return threshold. It does not prove realised execution, inventory
cost or market impact.

## Not Trading Signals

These labels describe future market-state outcomes for supervised forecasting
experiments. They are not trading signals and do not imply tradability. Later
phases must still handle temporal splits, overlapping labels, purged validation,
calibration and execution-aware validation before any cost-adjusted signal
quality can be studied.
