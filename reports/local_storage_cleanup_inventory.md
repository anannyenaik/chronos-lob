# Local Storage Cleanup Inventory

This note records a local-disk cleanup performed before the next experiment run.
It classifies every heavy local artefact, records what was preserved, and gives the
exact command needed to regenerate anything that was removed. Nothing tracked in
Git or used as public evidence was touched.

## Context

- Date: 2026-05-30
- Git commit at cleanup time: `ef0724fb55e595fffb7af6e616ebb1789cfaaac6`
- Branch: `main`
- Local repository size before cleanup: 45.45 GB
- Local repository size after cleanup: ~3.28 GB (projected; confirmed in final summary)
- Total reclaimed: ~42.17 GB

All removed items are local-only and were already ignored by `.gitignore`, so removing
them changes no committed file and no public evidence. The committed summary tables,
manifests, configs, source, tests and docs are the public record and were all retained.

## Recomputation cost warnings

- Re-extracting `extracted/` is fast (disk I/O only, no model fitting), as long as
  `BenchmarkDatasets.zip` is retained (it is).
- Re-preparing `data/processed/fi2010/` would require re-extraction plus the prepare
  step; the folds were therefore kept to avoid this.
- Rebuilding the feature-ablation `predictions.csv` set re-runs 900+ model fits and
  costs hours of CPU. The aggregated deltas are already retained, so this is only
  needed if row-level outputs are required again.
- Rebuilding the neural full-grid `predictions.csv` and checkpoints re-runs the full
  neural training grid and costs many hours of CPU. The committed summaries and the
  already-built `experiments/fi2010_execution_v3/` diagnostic do not need it.

## Forward dependency check

- `build-fi2010-execution-v3` and `build-fi2010-figures` consume the neural full-grid
  row-level `predictions.csv`. Both outputs are already built and committed
  (`experiments/fi2010_execution_v3/`, `reports/figures/`), and the final report reads
  their stored summaries, not the raw rows. So removing the grid `predictions.csv`
  does not break the current report or any committed artefact; it only blocks a
  from-scratch rebuild of execution-v3 or figures until the grid is re-run.
- The next planned run (proper-training neural subset) consumes `data/processed/fi2010`,
  which was retained, so it is unaffected.
- No retained workflow file depends on any removed artefact for its inputs beyond the
  regeneration commands listed above.
